张量就是数表

Tensor（张量）

Tensor 是用于数值计算的多维数组，三个核心属性：

  • shape：张量形状，例如 (2, 3)。
  • dtype：元素数据类型，例如 float32、int64。
  • device：计算设备，例如 cpu、mps。

其他属性：ndim 表示维度数量，numel() 表示元素总数。

创建 Tensor

Tensor 相比 Python List，支持高效的张量运算及 GPU 计算。

索引

  • t[i]：取第 i 行。
  • t[:, j]：取第 j 列。
  • t[-1]：取最后一行。
  • t[:, -1]：取最后一列。
  • t[0, 1]：取指定元素。

整数索引通常消除对应维度，切片索引保留维度。

沿轴聚合：dim

dim 指定被聚合的维度，而不是保留的维度。

假设 x.shape = (2, 3)：

  • keepdim=False：默认删除被聚合的维度。
  • keepdim=True：保留该维度，但长度变成 1。

矩阵乘法

矩阵乘法：A 的行与 B 的列对应相乘，再求和。

Shape 规则：

中间必须相等，结果保留两边。

  • a * b：逐元素相乘，支持广播。
  • a @ b：矩阵乘法。
  • torch.matmul(a, b)：矩阵乘法，支持批量矩阵乘等。

矩阵乘法是 Transformer 线性层和 Attention 的基础。

Device（计算设备）

.to() 返回目标设备上的 Tensor，不会直接修改原变量。

普通矩阵运算要求参与计算的 Tensor 位于兼容的设备上。

last_token_logits

Logits 是模型对候选 Token 的原始预测分数，不是概率。

模型输出 Shape：

提取最后位置的预测分数：

  • logits[0, -1, :]：取第一条序列最后位置的全部候选分数。
  • argmax()：返回最高分对应的 Token ID。

自回归生成只需要最后位置的 Logits 来预测下一个 Token。

核心总结

Tensor 是 LLM 推理的数据基础：Shape 决定结构，矩阵乘法完成特征计算，Device 决定计算位置，Logits 用于预测下一个 Token。

自回归

自回归基础概念

自回归（Autoregressive）：模型每次预测一个 Token，将其追加到序列，再继续预测。

核心流程：

Forward → Logits → Sampling → Append → 判断停止条件 → 循环

  • Forward：模型前向计算，输出 Logits。
  • Sampler：根据 Logits 选择下一个 Token。
  • Generation Loop：控制生成循环、Token 拼接与停止条件。

Token 与 Tokenizer

  • Token：模型处理文本的基本单位，可以是字、词、词片段或特殊符号。
  • Token ID：Token 在词表中的整数编号。
  • Tokenizer：负责文本与 Token IDs 之间的编码、解码。
  • input_ids：模型接收的整数 Tensor，单条序列 Shape 通常为 (1, L)。
  • EOS：序列结束符，用于提前终止生成。

模型预测的是下一个 Token 的分数，通过采样选出 Token ID，最后由 Tokenizer 解码成文本。

generate_naive：自回归生成循环

关键操作：

  • @torch.no_grad()：关闭梯度记录，减少推理开销。
  • model(ids)：模型前向计算。
  • logits[0, -1, :]：提取最后位置的候选分数。
  • torch.argmax()：贪心解码，选择最高分的 Token ID。
  • .item()：将单元素 Tensor 转为 Python 数值。
  • torch.cat(..., dim=1)：沿序列长度维度追加 Token。

停止条件：

  • max_new_tokens：限制最大新生成 Token 数量。
  • eos_token_id：生成 EOS 时提前停止，返回序列中包含 EOS。

KV Cache 优化原理

KV Cache 缓存历史 Token 在各层 Attention 中的 Key 和 Value，避免重复计算历史状态。

  • Prefill：处理完整 Prompt，建立初始 KV Cache。
  • Decode：逐 Token 增量计算，复用并更新历史 K/V。

KV Cache 是以空间换时间的优化：

  • 优点：减少重复计算，提高 Decode 效率。
  • 代价：需要额外内存保存历史 K/V。
  • 注意：新 Token 的 Query 仍需与历史 Key 计算 Attention。

后续 vLLM 使用 PagedAttention、KV Cache Block 管理等机制优化缓存内存利用率。

核心总结

  1. 自回归生成：逐 Token 执行 Forward → Sampling → Append。
  2. 生成循环与模型分离：模型负责计算 Logits，Generation Loop 负责生成控制。
  3. Stub Model：通过确定性假模型验证生成逻辑。
  4. Naive Generation：每轮重新计算完整历史序列，存在重复计算问题。
  5. KV Cache：缓存历史 K/V，实现增量推理，是高性能 LLM 推理的重要基础。

一句话总结：自回归要求逐 Token 生成，但不要求重复计算全部历史；KV Cache 通过以空间换时间提高推理效率。
